# 2026-11-12 Quizeey PO 보고서: 신고 보존 검증과 사용자 증가 방안

## 핵심 요약

오늘 신규 report export는 없고, 읽기 전용 DB 신고함에는 열린 건이 없었다. 기존 GitHub 열린 이슈의 신규 갱신도 없었다. 가장 높은 미해결 위험인 OPS-01의 신고 보존 SQL을 버전 관리된 [migration](../../../supabase/migrations/20261112232605_preserve_open_forum_reports.sql)으로 준비하고 격리 DB에서 검증했다. 소유자가 미처리 신고의 처리 시점까지 보존과 운영 적용을 승인하여 **운영 DB migration 적용 및 정의·권한 readback을 완료했다.** 실제 장기 미처리 신고의 보존 성과는 아직 관찰 전이다.

매일 블로그 글 한 편을 작성하도록 PO 스킬을 갱신하고, 오늘은 한식조리기능사 식품위생 원본 사례 글을 작성했다. 글과 개인정보 고지는 `fix/ops01-open-report-retention-20261112` 개발 브랜치에서 최종 로컬 검증을 통과했고 운영 Git 배포를 준비했다. 운영 게시 상태는 배포 후 별도 읽기 확인을 따른다.

## 완료

- 전용 로컬 PostgreSQL에 후보 SQL을 적용해 만료 open 신고의 반복 cleanup 후 보존·대기열 표시·해결, 만료 resolved 신고의 삭제, 권한 경계를 합성 자료로 확인했다. 비인가 역할의 private queue 직접 호출도 검사에 추가했다.
- 독립 검수자가 기존 함수·권한과 후보를 대조해 차단 결함을 찾지 못했다. 신고 사유의 장기 보존은 정책 결정이 필요하다고 지적했다.
- 공식 CLI로 로컬 migration을 만들고, [DB 검사 스크립트](../../../tools/modernization/test_database.py)와 [CI](../../../.github/workflows/modernization.yml)에 [보존 회귀](../../../supabase/tests/forum_report_retention.sql)를 연결했다. 빈 격리 클러스터에서 전체 migration을 처음부터 적용한 뒤 회귀, 권한·동시성·백업/복원 검사를 통과했다.
- 최초 `web`의 `npm run check:local` 종료 코드 0: 타입 검사, lint, 단위 183개, 빌드, 브라우저 112개, 광고 회귀 통과. 이 실행은 글 추가 전 OPS-01 검증 이력이다. 최종 글 수정본의 전체 재검사 결과는 아래에 기록했다. 운영 주소에 회귀 요청을 보내지 않았다.
- 성장 방안과 근거·측정·평가 날짜를 [기존 성장 계획](../growth-plan.md)에 기록했다. 공식 Cisco v1.1/v2.0 범위와 기존 CCNA 문항을 확인했고 새 5문항은 예정대로 별도 작성·검수한다.
- 승인된 운영 DB migration `20261112232605` 적용 후 실제 함수 정의를 읽어 해결된 신고만 30일 만료 정리 대상이고, 미처리 신고가 관리자 queue의 만료 필터에서 제외되지 않음을 확인했다. 익명·인증 사용자에게 private 함수 실행 권한은 없고 service_role만 허용된다. 운영 DB에 테스트 신고를 쓰거나 cleanup을 실행하지 않았다.
- [오늘의 한식조리 글](../../../web/src/components/KoreanCookingArticle.tsx)은 국내 GSC의 한식조리기능사 필기 의도와 실제 한식 문제 세트를 확인해 선정했다. 식약처·Q-net 공식 자료와 원본 사례 3개를 독립 검수했다. [PO 스킬](../../../.agents/skills/quizeey-po/SKILL.md)에 매일 한 편·중복 방지·실제 시험 경로 검증·로컬 품질 문턱을 추가했다.
- 양식조리 URL이 한식조리 ID 14를 보여 주는 기존 경로 결함을 로컬 브라우저에서 발견했다. 양식 글 초안의 학습 경로 검사 실패 뒤 오늘 글을 한식으로 전환했고, 기존 경로 결함은 OPS-06으로 분리했다.

## 성과

OPS-01은 **운영 DB migration 적용과 함수·권한 readback 완료**다. 현재 열린 신고가 없어 30일 넘는 실제 보존 사례는 아직 관찰되지 않았다. 사용자 증가와 기존 CCNA 글의 검색·학습 성과도 미측정이다. GROWTH-01의 비무작위 28일 관측은 12월 8일까지 진행한다. 신규 export가 없어 기존 GA4 표시 총계와 차원 행 합계 차이, 원천 확정일, 시험별 학습 시작 공백은 유지된다.

## 사용자 증가를 위한 우선 방안

| 우선 | 실행안 | 확인할 결과 |
| --- | --- | --- |
| 1 | 새 한국어 CCNA 글에서 기존 문제풀이로 가는 학습 경로를 측정하고, 11월 17~19일 원본 5문항을 작성·독립 검수한다. | 글의 유기검색 랜딩과 CCNA 학습 시작을 분리해 관찰. 새 문항 게시·효과는 아직 아님. |
| 2 | 기존 한국어 조리·SQLD·3D 페이지 중 최신 GSC에서 검색 의도가 명확한 한 페이지의 설명·제목·연습 링크를 개선한다. | 대상 페이지 검색 클릭, 자연검색 랜딩, 해당 시험 학습 시작을 같은 정의와 완결 기간으로 비교. |
| 3 | 기존 이어 풀기·오답/북마크 복습의 실제 이용 여정을 로컬에서 관찰하고 한 지점의 마찰만 개선한다. | 학습 완료와 동일 정의의 7일 재학습. 현재는 실행 ID와 모드별 수신을 확인해야 한다. |
| 4 | 미국·캐나다·일본·호주에서 기존 영어 시험 경로의 국가×페이지 검색 의도와 실제 학습 시작을 다시 확인한다. | 11월 23일 한 경로 파일럿 여부 결정. 소표본·차원 누락이면 보류. |

[Google Search Central](https://developers.google.com/search/docs/fundamentals/creating-helpful-content)은 원본성·학습자에게 유용한 내용과 정확한 제목을 권하고, [내부 링크 지침](https://developers.google.com/search/docs/crawling-indexing/links-crawlable)은 관련 페이지를 이해할 수 있는 링크를 권한다. 따라서 대량의 국가별 유사 페이지보다 기존 학습 의도에 맞는 한 경로 개선을 먼저 검토한다. GA4에서 `test_id`를 분석 차원으로 쓰려면 [맞춤 측정기준 등록과 실제 수신](https://developers.google.com/analytics/devguides/collection/ga4/event-parameters)을 확인해야 한다. 검색 클릭을 학습자 증가로, 이벤트 총수 비율을 실행별 완료율로 부르지 않는다.

사용자 증가 자체는 같은 GA4 속성·완결 28일의 **신규 사용자와 활동 사용자**로 확인한다. GSC 클릭·랜딩 세션·학습 시작은 서로 다른 단계의 보조 신호다. 현재 자료로는 해당 시험별 신규 사용자→학습 시작 전환율을 계산할 수 없다.

## 진행 중·대기

- OPS-01의 미처리 신고는 처리 때까지 30일을 넘어 보관될 수 있다. 매일 신고함을 확인하되 실제 장기 미처리 사례와 삭제 결과는 추후 관찰한다. 한·영 개인정보처리방침에는 처리 전 보존과 해결 후 최초 접수 30일 경과 시 정리 대상임을 명시했다. 신고 자체의 조치는 없었다.
- OPS-06: 양식조리 URL이 한식 문제를 보여 주는 기존 계약을 확인했다. 양식용 문제 자료와 원천 ID를 검증한 뒤 별도 수정한다.
- OPS-02의 기존 공개 자료 정리 범위는 결정 대기다. 이번 새 문서에는 비공개 지표·원문·식별자를 기록하지 않았다.
- 최신 GSC/GA4/AdSense 완결 기간과 GA4 `test_id` 수신을 확인할 새 export는 아직 없다.

## 소유자 조치 필요

OPS-01의 보존 정책과 운영 DB 적용은 승인·처리됐다. 양식조리 경로의 원천 시험 ID와 문제 자료가 별도로 확인되기 전에는 양식 전용 문제 링크를 게시하지 않는다. 성과 평가에는 다음 주간 export에서 완결 날짜·시간대·필터/행 제한과 GA4 `test_id` 맞춤 측정기준 수신 여부를 함께 확인하면 된다. 인증정보는 전달하지 않는다.

## 최종 로컬 게시 검사

한식 글의 최종 수정본으로 격리 DB/Auth fixture를 켜고 `npm run check:local`을 다시 실행해 종료 코드 0을 확인했다. 타입 검사, lint, 단위 183개, 빌드, 브라우저 114개, 광고 회귀가 통과했고 DB/Auth 브라우저 13개를 포함했다. 글의 모바일 접근성과 글→실제 한식 시험 문제풀이도 통과했다. fixture를 종료했고 두 포트의 리스너가 없음을 확인했다. 생성된 추적 테스트 산출물 세 개만 복원했다. 운영 웹 게시와 작은 읽기 확인은 Git 배포 후 별도 기록한다.
