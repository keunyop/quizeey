# 2026-11-17 Quizeey PO 보고 — SQLD LEFT JOIN 학습 글

## 핵심 요약

SQLD 학습자가 `LEFT JOIN`의 오른쪽 테이블 조건을 `ON`과 `WHERE`에 둘 때 결과가 달라지는 이유를 직접 계산해 볼 수 있는 원본 글을 게시했다. 실제 2026년 11월 SQLD 연습 회차로 연결했고, PostgreSQL 공식 문서와 별도 콘텐츠 검토로 설명을 확인했다. 첫 운영 빌드는 잠금 파일 누락으로 실패했으나 검증된 수정 커밋의 Git 배포가 READY가 됐고 영향 경로 3곳의 읽기 확인을 마쳤다. CCNA IPv4 문제 해결 문항 5개는 검수용 초안으로 남기고 제품에는 등록하지 않았다.

## 완료

- 신규 report 입력 0개를 처리 manifest와 파일 해시로 확인했다. 운영 DB의 미해결 문항·게시글 신고는 각각 0개였고, legacy GitHub 열린 이슈 번호 집합은 이전과 같은 48개였다. GitHub 조회에서는 수정 시각을 확인할 수 없어 본문 변경 여부는 판정하지 않았다. 신고 조치나 외부 메시지는 수행하지 않았다.
- [SQLD LEFT JOIN 글](../../../web/src/components/SqldLeftJoinArticle.tsx)에 직접 만든 회원·주문 사례, `ON` 조건의 3행과 `WHERE` 조건의 1행, 미매칭 `NULL`과 주문 부재의 차이, 선택지별 오답 이유를 담았다. [블로그 등록](../../../web/src/lib/blog.ts)과 11월 SQLD 원본 연습 경로를 연결했다. 별도 검토자가 PostgreSQL 18 공식 근거와 행 수를 재확인했다.
- [CCNA 문항 초안](../../seo/ccna-ipv4-troubleshooting-questions-draft-20261117.md)에 Cisco 공식 범위와 자체 주소 계산 5개를 기록하고 기존 23문항 및 공개 글과 중복을 대조했다. 한국어 문항 등록·채점·보기 회전·실제 렌더링은 검증되지 않아 미게시다.
- 필수 검사 중 설치된 Next.js 16.4.2의 보안 경고로 최초 빌드가 중단됐다. Next.js를 16.4.6으로 패치했고 운영 의존성 `npm audit --omit=dev`는 취약점 0건이다. 컴퓨터 종료 전의 검사는 성공으로 간주하지 않았다.
- 독립 출시 검토에서 차단 결함은 없었다. “원본 연습문제”로 읽힐 수 있는 소제목을 “2026년 11월 SQLD 연습문제”로 고쳤다. 그 뒤 전체 재검사에서 기존 영어 11월 시험 테스트가 버튼 활성화 전 Enter를 눌러 한 번 실패했다. 실패 화면과 로컬 집중 재검사로 경쟁 조건을 확인해 테스트에 버튼 활성화 대기를 추가했다. 실패한 실행은 출시 근거로 사용하지 않았고, 수정 후 최종 전체 검사가 통과했다.

## 검증과 출시

- 16.4.6 패치 후 `npm run check:local`을 처음부터 다시 실행해 종료 코드 0을 확인했다. 타입 검사·린트·단위 186개·빌드·브라우저 122개·광고 시뮬레이션 6개가 통과했다. 새 글의 목록→본문→SQLD 연습 이동과 모바일 밝음/어두움 접근성 검사도 통과했다.
- 격리 PostgreSQL/Auth fixture가 없어 관련 브라우저 13개는 skip했다. 이 실행만으로 DB·인증 흐름을 검증했다고 주장하지 않는다. 브라우저 검사는 로컬 `127.0.0.1:3100` fixture 서버만 사용했다.
- 검증된 커밋 `1c4a4b4`를 `master`로 fast-forward하고 Git push 한 번으로 보냈다. 원격 SHA는 일치했지만 Vercel 운영 배포는 `npm ci`가 `@emnapi/core`와 `@emnapi/wasi-threads` 선택 의존성 누락을 보고해 `ERROR`로 끝났다. `quizeey.com` 별칭은 이전 READY 배포에 연결돼 있어 새 글은 미게시 상태다. 자동 재배포는 하지 않았다.
- [잠금 파일](../../../web/package-lock.json)에 npm 레지스트리 메타데이터로 두 패키지 항목 21줄만 보강했다. 수정 전에는 로컬 `npm ci --dry-run`도 실패했고, 수정 후 Windows와 Linux x64 glibc dry-run 및 실제 로컬 `npm ci`가 통과했다. 깨끗한 설치 후 `npm run check:local`도 종료 코드 0으로 통과했다(단위 186개, 브라우저 122개 통과·13개 DB/Auth skip, 광고 6개). 운영 의존성 감사는 0건이다. Linux dry-run만으로 운영 빌드 성공을 가정하지 않고 실제 운영 `npm ci`와 READY를 별도로 확인했다.
- 소유자 승인 후 수정 커밋 `e949fa1`을 `master`에 fast-forward하고 Git push 한 번으로 보냈다. 원격 SHA와 Vercel production 배포 SHA가 일치했고, 운영 `npm ci`가 성공해 배포가 READY가 됐다. `quizeey.com` 별칭도 새 배포를 가리켰다. 새 글, 블로그 목록, 2026년 11월 SQLD 연습 경로 3곳만 읽기 GET으로 확인해 모두 HTTP 200과 예상 내용을 확인했다. 추가 배포나 호스팅 회귀·크롤링은 수행하지 않았다.
