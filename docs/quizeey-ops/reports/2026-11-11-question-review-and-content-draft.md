# 2026-11-11 문항 신고 검토와 CCNA 글 초안

## 오늘 선택과 결과

오늘의 신규 문항 신고를 기존 CCNA 글 일정에 앞서 확인했다. 신고 대상은 2026-10 자체 제작 한식조리 연습문항이다. 원본 데이터, 노출 순서, 채점 코드와 식품안전 공식 자료를 대조한 결과, 비누와 물로 손을 씻는 선택지가 올바른 정답이며 잘못 지정된 정답은 확인되지 않았다. 질문 표현과 해설은 더 명확하게 고치고 해당 문항에 직접 근거 링크를 추가했다. 신고 원문과 원천 식별자는 비공개 운영 기록에만 보관한다.

독립 검수에서는 생성 데이터의 변경이 이 문항의 질문·해설·출처에 한정되었고 보기, 정답, 순서, ID가 유지됨을 확인했다. 기존 저장 답안은 문항·선택지 ID와 당시 정오답을 사용하므로 이 정정으로 점수가 바뀌지 않는다. 과거 릴리스의 콘텐츠 해시는 그대로 보존하고 승인된 정정 한 건만 복원해 이전 스냅샷과 비교하도록 테스트를 보완했다.

CCNA 200-301 IPv4 서브네팅 한국어 글 초안도 작성했다. Cisco의 v1.1/v2.0 공식 시험 범위와 시행일, 세 예제 계산, 기존 영어 글과의 차이를 독립 검수했다. 검수에서 연습 링크가 의도한 자체 제작 회차를 열지 않는 문제를 찾아 회차를 명시하고 로컬 fixture에서 HTTP 200과 회차 표시를 확인했다. Cisco 원문은 공식 PDF로 연결했다. 글은 저장소 초안이며 제품 통합·게시 시점의 문구 재확인·로컬 품질 검사가 남아 있다. 원본 5문항도 아직 작성·게시하지 않았다.

## 검증·운영 상태

- `npm run check:local`의 첫 실행은 콘텐츠 정정에 따른 기존 전체 해시 고정 테스트 5개 실패로 중단됐다. 과거 해시를 갱신하지 않고 허용된 정정 기록을 대조하는 방식으로 수정했다.
- 수정 후 `npm run check:local` 종료 코드 0: 타입 검사, lint, 단위 테스트 183개, 빌드, 브라우저 테스트 97개와 광고 회귀가 통과했다. DB/Auth fixture가 없어 관련 브라우저 테스트 13개는 skip됐다. 이 실행으로 DB/Auth 흐름이 검증되지는 않는다.
- 브라우저 회귀가 사용하는 `127.0.0.1:3100` fixture 서버의 해당 문항 경로만 추가로 읽어 HTTP 200, 새 질문, 정답 보기와 공식 출처 표시를 확인했다.
- 변경은 개발 브랜치에서 준비했고 필수 로컬 검사와 독립 검수가 통과했다. 보고서의 최초 커밋 뒤 `master` Git push 한 번으로 릴리스했다. 원격 커밋 readback과 production READY·도메인 별칭을 확인했고, 영향 문항 한 경로에서 HTTP 200과 정정 문구·정답 보기·출처를 읽었다.
- 공개 문항 내용의 정정은 신고 원천 기록의 해결 처리가 아니다. 운영 신고는 미해결로 보존하며 별도 처리 권한 경계를 지킨다.

## 다음 순서

1. 원천 신고는 운영 읽기에서도 open이다. 정답 오류가 확인되지 않고 문구 정정은 반영됐으나 신고 해결·관리자 조치는 별도 승인 경계에 둔다.
2. 11월 13일까지 CCNA 글의 제품 통합안을 만들고 게시 시점의 문구·링크·로컬 품질을 검사한다. 11월 16일 게시 목표는 검수 통과가 조건이다.
3. 11월 17~19일 CCNA 원본 연습문항 5개의 답·해설·오답 이유·출처를 작성해 별도 검수한다. 11월 20일 소규모 게시 목표를 유지한다.
4. OPS-01 격리 DB/Auth 검증과 운영 DB 승인, OPS-02 공개 자료 범위 판단, GROWTH-01의 28일 관측은 미해결 상태로 이어간다.

새 지출, 광고 변경, 외부 발신, 운영 DB 변경은 없었다. GA4 표시 합계와 행 합계의 차이 등 이전 측정 제한도 그대로다.

## 소유자 후속 요청과 신고 처리

소유자가 미처리 오답 신고 확인과 처리를 별도로 요청했다. 운영에 이미 반영된 정정 문항 한 경로에서 질문·정답 보기·공식 근거를 다시 읽고, 원천 신고가 여전히 open임을 확인했다. 기존 검수상 정답 자체는 옳고 문구·해설은 수정됐으며 저장 점수에는 영향이 없다. 해당 신고 한 건을 감사 기록을 남기는 관리자 함수로 완료 처리했고, 별도 DB readback에서 resolved 상태·처리 시각·감사 대상 일치를 확인했다. 공개 기록에는 원문과 식별자를 남기지 않는다.
