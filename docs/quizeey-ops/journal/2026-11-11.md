# 2026-11-11 Quizeey PO 일지

## 시작 상태와 오늘 선택

- 전날 GROWTH-01 홈 학습 링크는 production READY 및 영향 경로 smoke 확인 후 관측 중이다. 효과는 아직 미측정이다. CCNA 한국어 원본 안내 글과 5문항 파일럿은 일정만 정해졌고 게시되지 않았다.
- 기존 우선순위인 OPS-01은 격리 DB/Auth 검증과 운영 DB 변경 승인 경계, OPS-02는 기존 공개 자료의 정리 범위 결정이 남아 있다. 두 항목은 이번 글 작업으로 해결된 것으로 간주하지 않는다.
- 기존 GitHub 열린 이슈를 재조회했다. 신규로 확인된 긴급 정답 오류는 없으며 기존 미해결 건의 상태를 유지한다. DB inbox는 로컬 명령 실행기와 Supabase 스킬 파일 접근 오류로 이번 시작 단계에서 재조회하지 못했다. 따라서 DB open 0건이라는 전날 결과를 오늘의 결과로 재사용하지 않는다.
- 오늘은 기존 계획의 한국어 CCNA 200-301 IPv4 서브네팅 원본 글 초안을 선택한다. 담당은 PO/Content 작성, 별도 검수자는 공식 범위·계산·기존 글 중복을 독립 확인한다.
- 완료 기준: Cisco 공식 시험 범위를 확인하고, 기존 글과 문항의 중복을 확인한 뒤, 검산 가능한 예제로 초안을 작성한다. 독립 검수와 로컬 품질 검사가 완료되어야 게시 후보가 된다.
- 기대 관측: 게시 후 CCNA 대상 학습 시작 및 해당 경로 유입. 지금은 시작 기준선과 성과를 확정할 수 없다. 새 비용은 없다.
- 게시 범위와 복구: 이번 글은 기존 CCNA 학습 경로와 연결하는 원본 교육 콘텐츠다. 게시 전에는 로컬 초안 상태로 둔다. 게시 후 오류가 발견되면 글만 되돌리고 관련 링크를 재검사한다.

## 실행 환경 메모

- 로컬 `exec_command`가 프로세스 생성 단계에서 `setup refresh had errors`로 실패한다. Git 상태 확인, 파일 목록/입력함 전수 대조, 로컬 회귀 검사를 이 경로로는 수행할 수 없다. 확인 가능한 로컬 문서와 연결된 읽기 도구로 안전한 조사부터 진행한다.

## 우선순위 변경: 새 문항 신고

- 승인된 명령 실행 경로에서 로컬 상태와 report 입력함을 재확인했다. 입력함 원본의 현재 체크섬은 모두 기존 private 처리 manifest에 있어 신규 export는 없다. 기존에 있던 Skill 수정은 이번 작업과 분리해 보존한다.
- 오늘 DB inbox를 읽기 전용으로 재조회한 결과 새 미해결 문항 신고 1건이 확인됐다. 전날의 open 0건을 오늘의 상태로 재사용하지 않는다. 원문·문항 식별자는 private 운영 상태에만 기록한다.
- 정답 오류 및 문제 설명 오타 주장으로 분류하고, CCNA 글의 게시 준비보다 현재 문항의 실물·정답·해설·관련 문항·저장 점수 영향 확인을 우선한다. 신고 내용 자체는 아직 검증된 오류가 아니다.
- CCNA 한국어 글은 로컬 초안을 작성했다. Cisco 공식 원문에서 v1.1 마지막 응시일(2027-02-02), v2.0 첫 응시일(2027-02-03), 각 IPv4 항목을 확인했다. 별도 검수자는 계산과 공식 항목 및 기존 영어 글과의 주제 차이를 확인했으나 로컬 파일 접근 장애로 초안의 전체 문구·제품 링크까지 검수하지는 못했다. 따라서 초안은 게시 후보가 아니다.

## 문항 원본 수정과 첫 회귀

- 신고 대상은 운영 DB 질문이 아니라 2026-10 자체 제작 세트의 문항이다. JSON 생성 원본과 실제 노출 문항을 대조했다. 기존 첫 선택지는 비누·흐르는 물 손 씻기이며 유일한 정답으로 표시된다. 식품안전 공식 안내도 식품 준비 전 비누와 물로 손 씻기를 명시한다. 정답 오류 근거는 발견하지 못했다.
- 어색한 질문 표현과 간결했던 해설을 명확하게 고치고, 해당 문항에만 식품 취급에 직접 맞는 공식 출처를 연결했다. 선택지·정답·문항 순서는 유지했다. 원본에서 제품 JSON을 재생성했다.
- 별도 검수자는 제시한 원문·수정문·공식 식품안전 자료를 독립 대조해 정답과 오답 이유에 차단 결함이 없다고 판단했다. 별도 검수자의 로컬 변경 diff 접근은 실패했으므로 실제 파일/ID 안정성은 로컬 검사와 별도 대조가 필요하다.
- 첫 `npm run check:local`은 typecheck·lint 후 단위 178개 통과, 기존 콘텐츠 전체 해시 고정 테스트 5개 실패로 종료 코드 1이다. 이는 의도한 문항 한 건의 내용 변경도 이전 릴리스 전체 해시를 바꾸기 때문이다. 필수 검사 실패 상태이므로 release는 차단했다.
- 무결성 검사를 제거하거나 과거 manifest 해시를 새 값으로 덮어쓰지 않는다. 기존 내용을 보존하면서 허용한 정정 한 건만 역사적 해시 비교에서 복원하는 방식을 검토한다. 여러 테스트에 걸친 변경이어서 `fix/2026-11-11-cooking-report` 개발 브랜치로 분리했다.

## 정정 범위와 독립 재검토

- 승인된 정정 기록에 이전/현재 문항 문구를 명시하고, 과거 릴리스의 그룹·문항 해시 비교 때 해당 한 문항만 이전 값으로 복원하도록 했다. 해시의 기대값을 바꾸지 않았으며 실제 현재 문구·출처·문항 ID가 기록과 일치해야 복원된다.
- 독립 검수자가 생성 데이터와 기존 버전을 전수 비교했다. 바뀐 문항은 1개이며 질문·해설·출처 외에는 바뀌지 않았다. 보기 4개·순서·정답·문항과 선택지 ID가 유지되고 공식 식품안전 자료와 새 해설이 일치한다. 차단 결함은 발견되지 않았다.
- 저장 학습 기록은 문항 ID에 연결된 선택지 ID와 정오답을 사용한다. 이번 정정은 해당 ID와 정답을 유지하므로 기존 점수와 학습 재개가 유지될 것으로 판단했다. 운영 데이터의 개인별 저장 결과를 읽거나 수정하지 않았다.
- 수정 뒤 타입 검사, lint, 단위 183개, 빌드는 통과했다. 전체 브라우저 회귀는 진행 중이다. DB/Auth fixture 부재로 관련 13개 검사는 skip된다. 이 검증만으로 운영 신고를 해결 처리하지 않는다.
- 브라우저 회귀의 로컬 fixture 서버에서 신고 문항 경로를 읽기 전용으로 한 번 확인했다. HTTP 200과 새 문구·정답 보기·공식 출처가 출력됐다. 배포 주소에는 회귀 요청을 보내지 않았다.

## CCNA 초안 검수 진행

- 독립 검수에서 글의 연습 링크가 회차를 지정하지 않아 의도한 자체 제작 문항 대신 기본 회차로 이동하는 문제를 찾았다. 초안 링크에 `verNbr=202610`을 명시하고 영어 자체 제작 연습 세트 전체로 이동한다는 설명을 덧붙였다. 아직 제품 글로 게시하지 않았다.
- 이어진 초안 전문 검수에서 세 서브넷 예제 계산·Cisco 범위와 시행일·시험 언어·기존 영어 글과의 차별성을 확인했다. 공식 범위 링크를 Cisco PDF로 바꾸고 주소 개수 설명을 보완했다. 로컬 fixture에서 지정 회차 링크의 HTTP 200 및 2026-10 표시를 확인했다. 게시 시점의 안내 문구와 제품 통합은 남아 있다.

## 로컬 최종 검증과 릴리스 대기

- `npm run check:local` 최종 종료 코드 0. 타입 검사·lint·단위 183개·빌드·브라우저 97개·광고 회귀 통과. DB/Auth fixture 부재로 브라우저 13개 skip이며 이 흐름은 미검증이다.
- 원격 `master`와 로컬 기준 커밋이 일치함을 읽기 확인했다. 현재 정정과 보고는 개발 브랜치에 준비되었고 운영 Git 릴리스 확인은 아직 남아 있다. 소유자의 기존 routine low-risk 릴리스 승인 범위에서 `master` push 한 번만 사용한다.

## 운영 반영 확인

- 검증한 개발 브랜치를 `master`에 fast-forward한 뒤 Git push 한 번으로 릴리스했다. 원격 `master` readback은 커밋 `4aed5d4`와 일치한다. Vercel production 배포는 같은 커밋으로 READY이며 `quizeey.com` 별칭이 연결됐다. CLI/API 추가 배포는 하지 않았다.
- 운영에서는 신고 문항 한 경로만 읽기 전용 GET으로 확인했다. HTTP 200과 수정된 질문·기존 정답 보기·공식 출처가 표시됐다. 회귀·크롤링·부하 검사는 운영에서 실행하지 않았다.
- 원천 신고를 읽기 전용으로 재확인한 결과 여전히 open이다. 정답 오류는 확인되지 않았고 문장 정정은 운영에 반영됐지만, 신고 해결·관리자 조치는 승인 범위 밖이므로 수행하지 않았다.
