# 2026-11-12 Quizeey PO 일지

## 시작 상태와 오늘 선택

- 전날 한국어 CCNA IPv4 서브네팅 글은 production READY와 세 경로의 읽기 확인을 마쳤다. 유입·학습 시작 성과는 아직 측정되지 않았다. 별도 원본 연습문항 5개는 작성·검수 전이다.
- 오늘 로컬 report 입력함 15개 원본의 체크섬을 처리 manifest와 비교한 결과 신규 파일은 없다. 따라서 새 성과 수치는 없고 기존 GA4 차원 행/표시 총계 차이와 원천 확정일 문제는 유지한다.
- 오늘 읽기 전용 DB 조회에서 visitor submissions와 forum reports에 open 상태는 없었다. 기존 GitHub 열린 이슈의 오늘 이후 갱신 건도 없었다. 기존 미분류·미검증 이슈는 해결로 간주하지 않는다.
- `master`는 `origin/master`보다 운영 문서 커밋 하나 앞서 있다. Skill 파일·참조 파일에는 기존 미커밋 작업이 있어 이번 범위와 분리해 보존한다.
- 오늘의 우선 작업은 기존 계획의 한국어 CCNA 200-301 IPv4 서브네팅 원본 5문항 파일럿이다. 안전·개인정보 우선 항목 OPS-01은 격리 DB/Auth 검증과 운영 변경 승인 경계가 남고, OPS-02는 공개 자료 정리 범위 결정이 남는다. 두 항목을 이번 콘텐츠 작업으로 해결 처리하지 않는다.
- 담당: PO/Content가 원본 문항을 작성하고, 별도 검수자가 Cisco 공식 범위·계산·정답·오답 이유·중복을 검토한다. Engineering은 기존 콘텐츠 스키마·학습 경로와 로컬 회귀를 검증한다.
- 완료 기준: 5문항의 시험 버전·언어·영역·난도·정답·해설·각 오답 이유·공식 근거·확인일·검수 기록을 남기고 중복과 학습 경로를 확인한다. 게시하려면 독립 검수와 전체 `npm run check:local`이 통과해야 한다.
- 기대 지표는 CCNA 해당 경로의 `practice_start`와 학습 완료다. 새 글 게시 직후라 기준선·인과효과는 미측정이다. 새 비용은 없다.
- 릴리스 범위는 검수된 5문항과 필요한 최소 링크로 제한한다. 필수 검사 실패 시 배포하지 않는다. 운영 게시 후 오류가 발견되면 해당 콘텐츠 변경을 검증된 커밋으로 되돌리고 영향 경로만 다시 읽는다.

## 성장 조사 병행

- 기존 GSC·GA4·AdSense 자료와 국가×시험 보고서의 제한을 유지하면서, 기존 페이지에서 관련 문제풀이로 이어지는 경로와 작은 검색 의도 개선안을 비교한다. 제안은 실행 우선순위·가설·필요한 측정·평가 시점까지 기록한다. 검색 클릭을 학습자 증가로, 국가 접속을 현지 시험 수요로 단정하지 않는다.

## 우선순위 재조정

- 국가·시험 후속 보고서의 약속된 일정은 CCNA 5문항 작성 11월 17~19일, 게시 목표 11월 20일이다. 오늘 시작 기록의 "우선 작업" 판단은 이 날짜를 놓쳤다. 신규 긴급 신고가 없는 현재에는 더 높은 심각도의 OPS-01 격리 DB/Auth 검증을 먼저 진행한다.
- OPS-01 완료 기준은 기존 신고 보존 SQL 후보를 현재 코드·schema와 대조하고, 격리 PostgreSQL/Auth fixture에서 open 만료 신고의 조회·보존, resolved 만료 신고의 정리, 권한을 검증하는 것이다. 운영 DB 변경은 별도 승인 대상으로 남긴다. 담당은 Engineering, 독립 검수자는 위험한 삭제 범위·권한·회귀를 확인한다. 기대 지표는 검증된 신고 데이터 보존이며 현재 운영 피해는 미확인이다.
- 복구는 로컬 fixture 재생성 및 SQL 후보 수정이다. 필수 검증이 끝나지 않으면 운영 적용·릴리스하지 않는다. CCNA 문항은 오늘 공식 범위와 기존 문항의 중복 조사만 진행하고 원래 작성 목표를 유지한다.

## OPS-01 격리 검증 진행

- 후보 SQL을 전용 `127.0.0.1:55432` 격리 PostgreSQL에 적용했다. 신고 보존 회귀 SQL은 종료 코드 0으로 통과했다. 만료 open의 반복 cleanup 후 대기열 표시·관리자 해결, 만료 resolved만 삭제, 정확한 만료 경계, 비인가 호출 거절을 합성 데이터로 확인했다. 운영 DB에는 쓰지 않았다.
- 별도 검수자는 기존 migration/RPC 권한과 후보 SQL·회귀 SQL을 읽어 기능·권한 차단 결함을 찾지 못했다. private 관리자 queue 직접호출 거절은 기존 hosted-boundary 검사에서 다루며, 이번 회귀 파일에도 추가할지 검토 대상으로 남겼다.
- Supabase CLI의 로컬 `migration new` 명령으로 버전 관리된 migration을 생성하고, 검사한 SQL 후보를 복사했다. 로컬 DB 검사 스크립트와 CI가 신고 보존 회귀를 실행하도록 연결했다. 새 migration을 처음부터 적용한 클린 fixture 재현과 전체 로컬 검사는 진행 중이다.
- 남은 승인 경계: 미처리 신고 사유가 기존 30일을 넘어 저장될 수 있는 보존 정책과 운영 DB 적용. 기존 공개 개인정보 안내는 신고 내용 저장을 알리지만 이 보존 기간을 명시하지 않는다. 운영 반영이나 기존 신고 상태 변경은 하지 않는다.

## 최종 로컬 검증과 상태 전이

- 격리 DB/Auth fixture를 켠 `npm run check:local`은 종료 코드 0. 타입 검사·lint·단위 183개·빌드·브라우저 112개·광고 회귀가 통과했다. 브라우저 112개에는 이전에 skip된 DB/Auth 13개가 포함된다. fixture 서버를 종료하고 55432/55433 포트가 비었음을 확인했다.
- 새 빈 격리 PostgreSQL 클러스터에서 모든 versioned migration을 순서대로 적용하는 `tools/modernization/test_database.py`가 종료 코드 0으로 통과했다. 신규 보존 회귀의 PASS 기록, 권한·동시성·14개 테이블의 백업/복원 대조를 읽었다. 두 실행 모두 운영 DB나 운영 URL에 회귀를 보내지 않았다.
- 로컬 검사에서 다시 생성된 추적 미리보기 이미지 두 개와 광고 증거 파일 한 개만 시작 상태로 복원했다. 기존 Skill 미커밋 변경과 원격보다 앞선 운영 문서 커밋은 이번 작업에 포함하지 않았다.
- OPS-01은 `정적검토 완료·로컬 기능 검증 완료·운영 정책/DB 승인 대기`로 이동한다. 운영 적용과 운영 효과는 미확인이다. 오늘 DB 재조회에서 두 신고함의 open은 0이고, GitHub 열린 이슈 48개의 기존 ID가 유지되며 11월 11일 이후 갱신 건은 없었다. 공개 문서에는 원문·ID·비공개 수치를 남기지 않았다.
- 완료: 버전 migration 준비, 격리 DB와 DB/Auth 포함 전체 회귀, 독립 검수, 성장 방안 조사·기록. 실패: 첫 `npm` 호출은 PowerShell 스크립트 실행 정책으로 거절됐으나 `npm.cmd`로 같은 검사를 실행해 통과했다. 새 지출·운영 신고조치·외부 발신·배포는 없다.
- 다음 큐: (1) 미처리 신고의 보존/비식별·삭제 정책과 운영 DB 승인 후 OPS-01 적용·readback, (2) OPS-02 기존 공개 자료 범위 결정, (3) CCNA 원본 5문항 11월 17~19일 작성·독립 검수, (4) 국가×시험 11월 23일 재평가, (5) GROWTH-01 12월 8일 관측 평가. 신규 지표 export가 없으면 성장 효과 판단은 미측정으로 둔다.
- 소유자 조치: 신고 사유의 30일 초과 보존 범위와 운영 DB 적용을 각각 결정한다. 다음 주간 export에는 원천의 완결일·시간대·행 제한과 GA4 `test_id` 실제 수신 여부를 함께 확인한다. [오늘 보고서](../reports/2026-11-12-ops01-growth.md)에 범위와 선택지를 기록했다.
- 운영 DB와 보존 정책이 얽힌 변경이므로 검증된 후보는 `fix/ops01-open-report-retention-20261112` 개발 브랜치에서 대기한다. 기존 Skill 미커밋 변경과 앞선 로컬 운영 문서 커밋은 그대로 보존했고 운영 `master`는 push하지 않았다.
- 최종 독립 재검토에서 새 migration의 실행 SQL이 기존 검증 후보와 동일하고, 추가 권한 테스트와 로컬/CI 연결에도 차단 결함이 없음을 확인했다. 기술적 로컬 검증은 완료됐으나 정책 승인·운영 DB 적용·운영 readback은 별도 단계로 남는다.

## 소유자 승인 후 재개: 신고 보존과 오늘의 글

- 소유자가 2026-11-12 대화에서 미처리 신고 사유를 해결 시까지 30일 넘게 보존하는 정책과 정확한 OPS-01 운영 DB migration 적용을 승인했다. 운영 프로젝트 ID를 확인하고 적용 전 migration 목록·함수 권한·만료 해결 신고 0건을 읽었다. 원본 SQL의 삭제 조건은 `resolved` 상태에 한정되며, 현재 만료된 해결 신고가 없어 적용 자체로 삭제된 신고는 없다.
- 승인된 SQL을 Supabase migration 도구로 운영 DB에 한 번 적용했다. 도구가 기록한 버전은 `20261112232605`이며, 저장소 migration 파일명도 이 버전에 맞췄다. 적용 후 목록에서 해당 버전을 확인하고 운영 함수 정의의 `state='resolved' and expires_at<now()` 조건, 관리자 queue의 만료 open 필터 제거, 익명·인증 사용자 실행 거절과 service_role 실행 허용을 읽기 확인했다. 운영 데이터에 합성 신고를 쓰거나 cleanup을 실행하지 않았다. 운영 효과는 실제 장기 미처리 신고가 생긴 뒤 확인할 수 있다.
- 사용자가 daily PO 스킬에 매일 블로그 글 1개 작성과 오늘 글 추가를 요청했다. 오늘은 한국 GSC 검색어·페이지 자료에서 양식조리기능사 필기 의도가 확인되고 기존 관련 글이 없다는 점을 근거로 `양식조리기능사 필기`를 주 키워드로 선정했다. 미국·캐나다는 검색 근거가 작고, SQLD·3D·CCNA에는 최근 글이 있으므로 제외했다. 원천 날짜·행 제한과 비공개 수치는 private 자료에만 둔다.
- 글은 식약처의 손씻기·교차오염·보관온도 지침과 Q-net 종목 페이지를 근거로 원본 사례를 작성한다. 기존 양식조리기능사 문제풀이로 연결하고 정답/근거·모바일·키보드·검색 메타데이터를 검수한다. 게시 후 28일간 해당 글의 GSC 클릭, 자연검색 랜딩, 해당 시험의 학습 시작을 별도 관찰한다. 기대 효과는 가설이며 현재 신규 사용자 증가는 미측정이다. 로컬 필수 검사 실패 시 게시하지 않고, 운영 오류 시 글·내부 링크만 검증된 이전 커밋으로 되돌린다.
- 로컬 브라우저 검사에서 양식조리 URL이 한식조리 ID 14의 문제 세트를 표시해, 양식 글→양식 문제 경로가 성립하지 않는 것을 확인했다. 필수 검사는 이 새 글의 학습 링크가 없어서 실패했고, 검사를 중단했다. 기존 legacy route 계약이 양식 경로를 한식 ID에 연결한다. 운영 자료를 임의로 재배치하지 않고 별도 결함으로 후속 조사한다.
- 오늘 글의 타깃을 실제 문제 세트가 있는 한국 `한식조리기능사 필기`로 재선정했다. 한국 GSC에서 해당 질의·시험 페이지의 검색 수요가 확인되고, 새 글의 위생 사례는 이 시험에도 관련된다. Q-net 한식조리기능사 종목 번호 7910을 다시 확인하고, 글의 이름·본문 사례·연습 링크를 한식 기준으로 고쳤다. 로컬 전체 검사를 최종 수정본으로 재실행한다. 보존 정책 변경은 한·영 개인정보처리방침에 실제 처리 시점과 해결 후 30일 정리 조건을 명시했다.
