## 소유자 승인 후 운영 DB 후속 반영

- 소유자는 준비된 해설·공식 출처 보강의 운영 DB 적용을 승인했고, 앞으로 검증된 정기 운영 반영은 재승인 없이 진행하도록 지시했다. 이 상시 승인을 루트 지침·운영 정책·PO 스킬에 기록한다. 검수·로컬 검증·현재 선행조건·복구·반영 후 읽기 확인은 유지한다.
- 대상은 독립 검수와 격리 DB 정상/거부/복구 9건을 통과한 해설·출처 수정뿐이다. 현재 운영 문항과 신고를 다시 읽어 준비된 원문 hash·수정 시각·시험/회차·보기·정답 및 빈 해설/출처와 일치함을 확인했다. 정답·문항·선택지·저장 점수·신고 상태를 변경하지 않는 완료 조건으로 진행한다.
- 같은 트랜잭션에서 신고와 회차 선행조건도 재확인하고 문항·보기를 잠근다. 정확한 해설·출처와 불변 조건을 commit 전에 확인하고, commit 후 별도 DB 읽기와 제한된 해당 문항의 운영 읽기로 반영을 확인한다. 실패 또는 불확실한 결과는 먼저 재조회하며 맹목적으로 재실행하지 않는다.

- 운영 적용과 동일한 전체 트랜잭션의 격리 DB 정상 commit/readback, 신고 상태 변경 거부, 회차 변경 거부 3건이 통과했다. 기존 검수 SQL의 정상/선행조건 거부/복구 9건 영수증도 확인했다. 별도 검수자가 SQL 원문 해시와 추가 잠금·commit 전 불변 확인을 검토했으며 운영 사용자 정의 trigger가 없음을 원천 metadata로 확인했다.

- 승인된 운영 DB 트랜잭션을 한 번 실행해 commit했고 별도 DB 조회에서 준비된 해설·출처 문자열의 정확한 일치와 원문·보기·정답 불변을 확인했다. 해당 문항 운영 GET 한 건도 HTTP 200이며 새 해설·공식 링크·현재 정답이 출력됐다. 문항은 verified_live이고 신고 상태는 별도 open으로 유지한다. 새 앱 배포나 전체 호스팅 검사는 하지 않았다.
- 실제 적용 revision을 저장하고, 그 revision 및 정확한 해설·출처·보기와 일치할 때만 작동하는 복구 SQL을 준비했다. 운영 적용 결과 영수증의 첫 텍스트 추출은 경계 문구를 잘못 잡아 실패했으나 저장된 응답을 올바른 경계로 다시 읽어 검증했다. DB 쓰기를 재실행하지 않았다.
- 상시 승인 변경: 검증된 정기 앱·콘텐츠 배포와 운영 DB 수정은 재승인 없이 진행한다. 현재 상태/revision·검수·적용 가능한 로컬 검사·복구·반영 후 읽기 확인을 유지한다. 신고 종결·모더레이션 등 별도 조치 권한과 혼동하지 않도록 정책을 명시했다.
