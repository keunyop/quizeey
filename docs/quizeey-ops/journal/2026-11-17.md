## 진행 기록
- 로컬 명령 실행 도구가 `setup refresh had errors`로 시작되지 않는다. 공유된 로컬 파일 페이지로 이전 상태·일지·보고서·운영 정책을 읽었다. Git 작업트리 확인과 로컬 검사는 아직 실행하지 못했다.
- 승인된 실행 경로로 로컬 작업트리를 읽었다. 어제의 출시 상태 정합화 문서 4개가 미커밋 상태이며 오늘 작업과 함께 보존한다. report 입력함 18개 파일의 SHA-256은 처리 manifest 18개 항목과 모두 일치해 신규 업로드가 없다. 운영 DB의 문항·피드백 및 댓글 신고 open은 각각 0건이고, legacy GitHub 열린 48개 이슈의 번호 집합도 어제와 같다. GitHub 조회에는 수정 시각이 없어 본문 불변까지 확인하지 않았다.
- 오늘 글 후보는 SQLD `LEFT JOIN`에서 오른쪽 테이블 조건을 `ON`에 두는지 `WHERE`에 두는지에 따른 결과 차이다. 전날의 집계 전·후 필터 글 및 기존 COUNT 글과 다른 학습 문제다. 선택 근거는 기존 GSC Web 2026-08-14~11-13의 SQLD 관련 검색어와 가이드 페이지 관측(서로 다른 차원), 그리고 실제 2026-11 SQLD 원본 세트의 LEFT JOIN·미매칭 행 문항이다. 특정 세부 검색어 수요와 동일 방문 전환은 확인되지 않았다. 대안인 CCNA 서브넷 계산은 이미 11월 11일 글과 기존 문항에 사례가 있어 중복 위험이 높다.
- 로컬 fixture `http://127.0.0.1:3000/sqlp-developer?verNbr=202611`을 열어 시험명이 SQLD이고 2026-11 원본 연습 20문항이며 첫 문항이 회원 LEFT JOIN 행 수를 묻는 것을 확인했다. 정답 보기의 표시 순서는 회전하므로 글에서 보기 번호를 특정하지 않는다. 새 글의 원본 예시는 별도 회원·주문 자료로 구성한다. PostgreSQL 18 공식 `JOIN`/`WHERE` 문서에서 outer join의 미매칭 행 확장과 `ON`·`WHERE` 조건 위치에 따른 결과 차이를 확인했다.
