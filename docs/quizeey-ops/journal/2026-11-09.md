성과 확인: 다음 실행이 질문 없이 일지에서 작업을 고르는지, 동일 작업을 중복 생성하지 않는지, release 상태를 정확히 기록하는지 확인한다. 제품 사용자·수익 지표 변화는 이 운영문서 변경으로 주장하지 않는다.

복구: 문서/Skill 문제는 해당 commit revert로 복구한다. master push 외 Vercel CLI/API 배포는 사용하지 않는다.

## 진행 기록

- 공식 Analytics Data API는 user account와 service account 인증을 지원하고 `analytics.readonly`와 숫자 property ID가 필요함을 확인했다.
- Search Console API는 OAuth 2.0과 `webmasters.readonly`를 지원하며 property 권한이 필요함을 확인했다.
- AdSense Management API는 service account를 지원하지 않고 Installed Application OAuth와 `adsense.readonly`가 필요함을 확인했다.
- 로컬 command runner가 `setup refresh had errors`로 새 프로세스 생성을 막고 있다. 파일 읽기/patch는 정상이며 required check·git 전환·push는 현재 대기다. 이 상태에서는 release하지 않는다.
- 변경한 Skill, AGENTS, 연결 안내, 일지와 상태 파일을 로컬 파일 브라우저로 다시 읽었다. `state.json`은 정상적으로 parse되며 다음 실행이 이 일지를 가리킨다.
- 별도 에이전트의 command 기반 검수도 같은 host process 오류로 실행되지 못했다. 독립 검수가 끝난 것으로 표시하지 않는다.

### 검증과 저장 결과

- 업로드 3종의 파일 크기·SHA-256·차원·실제 기간을 private manifest에 기록했다. 처음에는 처리 이력이 비어 있었고 중복 파일은 없었다.
- GA4: 내부 기간과 모든 날짜가 일치하고 필수열·수치·날짜/이벤트 키가 유효했다. 파일명 기간은 다르므로 내부 날짜를 사용했다. 학습 이벤트 중 한 종류는 관측되지 않아 0으로 채우지 않았다. 관측일 분포가 고르지 않고 집계 완료일이 명시되지 않아 최근 28일 비교와 실행별 완료율을 만들지 않았다.
- GSC: 파일 내부 시트/열 이름이 깨졌고 파일명과 차트 범위가 다르다. 검색어 사용은 차단했다. AdSense: Date 차원 대신 Platform 차원이므로 일별 보고서로 사용할 수 없다. 두 파일은 재시도 대상이다.
- 검증된 GA4 이벤트 집계만 ignored private baseline에 저장하고 readback한 뒤 manifest를 갱신했다. 별도 readback에서 baseline과 manifest의 checksum 일치, 처리 1건·차단 2건을 확인했다. 원본 파일과 비공개 수치는 공개 문서에 기록하지 않았다.
- 현재 DB에 open 신고는 없었고 기존 GitHub 미해결 목록은 그대로였다. 읽기 집계만 확인했으므로 신고 cursor나 처리 상태를 올리지 않았다.
- 앱 코드 변경·DB 쓰기·외부 메시지·commit·push·배포는 없었다. 이번 실행에서 로컬 앱 회귀, DB/Auth fixture, 독립 보고서 검수는 수행되지 않았다. 이전 기반 변경은 계속 release 대기다.
