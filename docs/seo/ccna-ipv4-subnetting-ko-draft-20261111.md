# CCNA IPv4 서브넷 계산: 주소 범위로 게이트웨이 설정 점검하기

> 2026-11-11 원본 글 초안. 게시 전 콘텐츠 검수와 로컬 품질 검사가 필요하다. 이 글의 예제는 직접 만든 연습 자료이며 Cisco의 실제 시험 문항이 아니다.

## 먼저 시험 버전을 확인하세요

Cisco의 [200-301 CCNA v1.1 공식 범위](https://learningcontent.cisco.com/documents/marketing/exam-topics/200-301-CCNA-v1.1.pdf)는 **1.6 IPv4 주소 지정과 서브네팅 설정·검증**을 포함한다. Cisco가 공지한 v1.1의 마지막 응시일은 **2027년 2월 2일**이다. **2027년 2월 3일**부터 응시하는 [v2.0 공식 범위](https://learningcontent.cisco.com/documents/marketing/exam-topics/200-301_CCNA_v2.0_Exam_Topics_PDF.pdf)는 **1.3 IPv4 주소 설정·할당·서브네팅 문제 해결(공인·사설 주소)**을 포함한다. 아래 계산은 두 범위를 공부할 때 쓰되, 실제 응시 버전의 전체 범위는 공식 안내에서 다시 확인하자. 한국어는 이 글의 설명 언어다. Cisco가 현재 안내하는 시험 언어는 영어와 일본어다.

IP 주소와 프리픽스만 보고 같은 네트워크인지 판단할 수 있으면, 게이트웨이 주소나 서브넷 마스크를 잘못 입력한 경우도 더 빨리 찾을 수 있다. **주소 블록을 찾고 → 네트워크·브로드캐스트 주소를 표시하고 → 호스트와 게이트웨이의 범위를 대조**하는 순서로 연습하자.

## 예제 1: 203.0.113.142/26의 주소 블록

`/26`은 32비트 IPv4 주소에서 네트워크에 26비트, 호스트에 6비트를 쓴다는 뜻이다. 마스크는 `255.255.255.192`다. 마지막 옥텟의 블록 크기는 `256 − 192 = 64`이므로 시작점은 `0, 64, 128, 192`다. `142`는 `128~191` 블록에 있다.

| 항목 | 결과 | 확인 방법 |
| --- | --- | --- |
| 네트워크 주소 | `203.0.113.128/26` | 142보다 작거나 같은 블록 시작점 128 |
| 브로드캐스트 주소 | `203.0.113.191` | 다음 블록 시작점 192의 바로 앞 |
| 일반 LAN에서 쓸 수 있는 호스트 | `203.0.113.129`~`203.0.113.190` | 양 끝 네트워크·브로드캐스트 주소 제외 |
| 주소 개수 | 전체 64개, 일반적인 사용 가능 주소 62개 | `2^6 = 64`, 그중 양 끝 2개 제외 |

**설정 점검:** 호스트를 `203.0.113.142/26`, 기본 게이트웨이를 `203.0.113.129`로 입력했다면 두 주소는 같은 `/26`에 있다. 게이트웨이를 `203.0.113.65`로 입력했다면 그 주소는 `203.0.113.64/26`에 속한다. 일반적인 직접 연결 LAN 설정에서는 호스트 주소·마스크·게이트웨이 값과 장비의 실제 구성을 다시 확인해야 한다. 이 주소 계산만으로 케이블, VLAN, 라우팅 등 다른 원인을 배제할 수는 없다.

가장 흔한 실수는 `142`를 가까운 시작점으로 반올림하거나, 전체 주소 64개를 전부 호스트 주소로 세는 것이다. **현재 주소 이하의 시작점**을 찾고, 다음 시작점 바로 앞에서 블록을 끝내자.

이 `/26`의 사용 가능한 주소 62개에는 기본 게이트웨이에 배정한 주소도 포함된다. 다른 장비에 배정할 때는 그 주소를 빼고 계산해야 한다.

## 예제 2: `/23`은 마지막 옥텟만 보면 틀린다

사설 주소 `10.20.35.10/23`을 보자. 마스크는 `255.255.254.0`이다. 마지막 옥텟이 아니라 **세 번째 옥텟**에서 블록이 바뀐다. `256 − 254 = 2`이므로 세 번째 옥텟의 블록은 `… 32~33, 34~35, 36~37 …`이다. `35`는 `34~35`에 들어간다.

- 네트워크: `10.20.34.0/23`
- 브로드캐스트: `10.20.35.255`
- 일반적인 사용 가능 호스트: `10.20.34.1`~`10.20.35.254`
- 호스트 비트 9개 → 전체 `2^9 = 512`개, 일반적인 사용 가능 주소 510개

`10.20.34.200`과 `10.20.35.10`은 이 `/23`에서는 같은 네트워크다. 세 번째 옥텟이 다르다는 이유만으로 다른 서브넷이라고 판단하지 말자. 반대로 한쪽 장비의 마스크가 `/24`라면 같은 주소 쌍을 서로 다르게 판단할 수 있다. 실제 연결 문제에서는 **두 장비의 IP와 마스크를 각각** 확인해야 한다.

## 답을 펼치기 전에 직접 풀어 보기

1. `198.51.100.173/28`의 네트워크 주소, 브로드캐스트 주소, 일반적인 사용 가능 호스트 범위는?
2. 같은 호스트의 기본 게이트웨이를 `198.51.100.177`로 입력했다. 호스트와 같은 `/28` 블록에 있는가?

<details><summary>정답과 해설 보기</summary>

`/28`의 마스크는 `255.255.255.240`, 블록 크기는 16이다. `173`은 `160~175` 블록에 있으므로 네트워크는 `198.51.100.160/28`, 브로드캐스트는 `198.51.100.175`, 일반적인 호스트 범위는 `198.51.100.161`~`198.51.100.174`다. `177`은 다음 `176~191` 블록에 있으므로 같은 `/28`에 있지 않다. `177`의 숫자가 173과 가깝다는 사실은 서브넷 판단에 영향을 주지 않는다.

</details>

틀렸다면 `내가 고른 시작점 / 실제 시작점 / 마스크에서 블록 크기를 구한 옥텟`을 한 줄로 기록하자. 새 주소를 넣어 다시 계산해 보면 규칙을 외웠는지 확인할 수 있다.

## 다음 연습

[CCNA 200-301의 2026-10 영어 자체 제작 23문항 연습 세트](/ccna-200-301?verNbr=202610)에서 네트워크 주소·마스크 관련 문항을 찾아 먼저 계산한 뒤 답과 해설을 대조하자. 이 링크는 해당 회차 문제풀이로 이동하며 주제별 필터는 없다. 이 글의 예제와 연결된 새 원본 5문항은 별도 검수 후 게시할 예정이다. 기존 세트를 Cisco의 공식 기출문제로 해석하지 말자.

영어로 같은 기본 계산을 다시 읽고 싶다면 [IPv4 subnetting worked examples](/en/blog/ipv4-subnetting-practice)을 참고할 수 있다. 영어 글은 `/26`, `/27`, `/20`의 주소 계산 자체에 집중하고, 이 글은 게이트웨이 주소·마스크 설정을 점검하는 순서에 집중한다.

일반적인 브로드캐스트 LAN 서브넷의 호스트 수를 설명했다. `/31` 지점 간 링크와 `/32` 단일 주소에는 끝 주소 두 개를 제외하는 규칙을 그대로 적용하지 않는다. 실제 네트워크 설정은 토폴로지와 장비 설정을 함께 확인해야 한다.
