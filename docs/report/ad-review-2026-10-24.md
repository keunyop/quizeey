# Quizeey 광고 수익·노출 검토 — 2026-10-24

사용자가 제공한 AdSense 미리보기 스크린샷 3장과 이 폴더의 CSV 4개를 분석했다. 사용자는 AdSense–GA4 연결, 맞춤 정의 4개 등록, 보고서 제공을 완료했다고 확인했다. 계정에 직접 접속하여 저장 상태나 이벤트 수신을 검증한 것은 아니다. 이번 검토는 앱 코드 변경·계정 설정 변경·배포를 포함하지 않는다.

## 결론

현재 자료로 광고가 UX를 얼마나 악화시키는지 또는 수익을 가장 높이는 노출량을 확정할 수는 없다. 자동 변경부터 고정하고, 수익 기여가 작은 Ad intents를 첫 정리 실험 후보로 삼는 편이 합리적이다. In-feed와 In-page는 합쳐 수익의 57.8%이므로 유지 후보이며, Anchor와 Vignette도 각각 20.3%, 13.8%의 수익을 차지한다. 형식 전체를 동시에 끄지 않는다.

이 분석은 앞서 실제 보고서 없이 제안했던 '전면 광고 간격부터 변경'보다 우선하는 실험 순서 제안이다. 관측 수익 비중은 인과효과나 삭제 후의 예상 손실률이 아니다. 광고를 제거하면 다른 형식의 수요·노출·방문 행동도 바뀔 수 있다.

- `adsense_report_플랫폼별.csv`: 3개 플랫폼, **$9.37**, **9,328 노출**. 날짜·사이트 필터·시간대 정보는 CSV에 없다.

## 광고 형식별 결과

수익 비중 = 해당 형식의 표시 수익 ÷ $9.37. 아래 노출 RPM은 표시 수익 ÷ 광고 노출 수 × 1,000으로 계산한 값이며 Page RPM과 다르다.

| 형식 | 수익 USD | 수익 비중 | 노출 | 계산한 노출 RPM USD | Active View Viewable |
| --- | ---: | ---: | ---: | ---: | ---: |
| In-feed | 3.06 | 32.7% | 1,997 | 1.53 | 70.41% |
| In-page | 2.36 | 25.2% | 2,543 | 0.93 | 47.84% |
| Anchor | 1.90 | 20.3% | 2,291 | 0.83 | 85.90% |
| Vignette | 1.29 | 13.8% | 957 | 1.35 | 89.41% |
| Side rail | 0.56 | 6.0% | 1,469 | 0.38 | 92.47% |
| Ad intent anchor | 0.12 | 1.3% | 39 | 3.08 | 43.48% |
| Ad intent chip | 0.06 | 0.6% | 25 | 2.40 | 31.58% |
| Ad intent link | 0.02 | 0.2% | 7 | 2.86 | 28.57% |

- Ad intents 3종 합계는 **$0.20, 71노출, 수익 비중 2.13%**다. 적은 노출 때문에 계산 RPM이 높아 보여도 주력 형식으로 확대할 근거가 되지 않는다.
- In-page의 가시성 47.84%는 배치 검토 대상이다. Google은 Multiplex Auto ads도 보고서의 In-page 형식으로 조회하도록 안내한다. 따라서 $2.36 전체를 수동 Display 슬롯 또는 Multiplex 하나의 수익이라고 단정할 수 없다. 분리하려면 Ad unit 또는 Auto ads/manual 출처 구분이 가능한 보고서가 필요하다. [Multiplex 보고 방식](https://support.google.com/adsense/answer/16532969?hl=en)
- Active View Viewable의 분모는 **측정 가능한 노출**이다. 전체 노출 수를 가중치로 써서 정확한 통합 가시성을 계산하지 않았다. 가시성이 높다고 UX가 좋다는 뜻도 아니다. [Google의 측정 정의](https://support.google.com/adsense/answer/3481946?hl=en)

모바일 개선이 중요하지만 제공된 광고 수익의 다수는 데스크톱에서 발생했다. 이는 광고 노출 비중이며 GA4 방문자 기기 비중은 아니다. 형식×플랫폼 교차 보고서가 없어 어느 형식이 모바일 수익을 만들었는지는 알 수 없다.

일별 합계의 광고 노출/AdSense 페이지 조회는 **3.26회**다. 이는 페이지 조회당 기간 평균 광고 노출 수이며, 한 화면에 동시에 광고 3.26개가 표시되었다거나 사용자 한 명에게 그만큼 노출되었다는 뜻은 아니다.

2026-10-19~10-23의 Page RPM은 표시 수익으로 계산하면 $1.85, 광고 노출/페이지 조회는 2.49회다. 그 이전 9/25~10/18의 값은 각각 $3.93, 3.62회다. 낮아진 값이 광고 변경 때문이라는 인과 해석은 불가능하다. 특히 이 하락 구간은 10/23 광고 개선 배포보다 먼저 시작됐고, 보고서가 새 버전 배포 후의 충분한 완결 일자를 포함하지 않는다.

## GA4에서 확인한 것과 부족한 것

- Active users 1,222, New users 1,125, 평균 참여 시간/Active user 약 **3분 23초**, 전체 이벤트 38,310.
- Session source / medium 표의 세션 합계 **1,984**, Page title and screen class 표의 Views 합계 **3,196**.
- 최상위 '양식조리기능사 기출문제' 제목은 961 Views로 전체 표의 약 30.1%다. 이후 UX 점검은 홈뿐 아니라 실제 사용량이 많은 학습 페이지를 포함한다.
- 현재 Snapshot에는 이벤트 이름별 practice_start/answer_submit/practice_result/practice_complete, ad_policy/practice_mode 값, 연결된 광고 수익, 기기별 학습 퍼널이 없다.
- 따라서 학습 완료율, 첫 응답 전 이탈, 동일 집단의 방문당 광고 수익, 광고 변화에 따른 7일 재방문 효과를 아직 계산할 수 없다. 전체 이벤트 수나 페이지 Bounce rate로 이를 대신하지 않는다. New users를 Active users에서 빼서 재방문율로 계산하지 않는다.
- GA4에서 등록한 맞춤 정의가 보이더라도 실제로 `ad_policy=balanced_v1`과 학습 이벤트가 수신되는지, 새 날짜의 보고서에 나타나는지는 별도 확인이 필요하다. 이전 완료 이벤트와 새 완료 이벤트의 정의가 다르므로 배포 전후 원시 완료 횟수를 직접 비교하지 않는다.

Ad Settings Preview는 편집/예시 화면이다. 스크린샷만으로 변경 저장 완료, 실제 광고 크기, 실제 동시 노출 수, 또는 진행 중인 실험의 존재를 확정하지 않는다. `0 in-page ads` 역시 이 미리보기의 표시이며, 전체 사이트가 광고 없이 운영된다는 의미로 해석하지 않는다.

미리보기에는 큰 Anchor 예시와 하단 광고 요소가 함께 보인다. 실제 모바일 UX 점검 후보이지만 이 예시 자체를 실제 사용자 노출 증거로 사용하지 않는다.

## 다음 조치 순서

1. **자동 변경 고정:** Ads → quizeey.com Edit → Auto optimize에서 Auto-apply experiment winner 체크를 먼저 해제하고, 수동 관찰/실험 중에는 Auto optimize도 OFF로 두는 것을 권한다. Apply to site → Apply now → Save로 저장한다. 광고 형식 전체를 끄는 작업과 구분한다. 현재 광고 형식 체크는 이 단계에서 일괄 변경하지 않는다. Google은 자동 실험에서 광고 형식이나 세부 설정을 바꿀 수 있다. [자동 최적화](https://support.google.com/adsense/answer/9141298?hl=en), [저장 절차](https://support.google.com/adsense/answer/15876143?hl=en)
2. **실험 상태 확인:** Optimization → Experiments의 Running 항목이 있는지 확인한다. 있으면 이름·변형·현재 결과를 확인한 뒤 기준 설정을 정한다. Keep original은 단순 일시정지가 아니라 원래 설정으로 되돌리고 실험을 종료하는 동작이다. [공식 FAQ](https://support.google.com/adsense/answer/6321880?hl=en)
3. **추가 확인은 Advanced settings 한 화면부터:** Overlay formats → Advanced settings를 펼쳐 Vignette ad frequency, Allow additional triggers for vignette ads, 앵커 위치·동적 확장 옵션을 확인한다. 이미 긴 전면 광고 간격을 임의로 10분으로 줄이지 않는다. [세부 설정](https://support.google.com/adsense/answer/9305577?hl=en)
4. **계측 기준선:** 새 맞춤 정의와 학습 이벤트 수신을 확인한 뒤, 자동 설정을 고정한 상태에서 완결된 날짜 기준 약 14일을 관찰한다. 보고서 시간대·호스트·기간을 맞추고 실험/설정 변경 날짜를 기록한다. 14일은 운영 점검의 시작점이지 통계적 승자 판정을 보장하는 기간이 아니다.
5. **첫 실험 후보:** Intent-driven formats에서 현재 Ad intents 활성 여부를 먼저 확인한다. 현재 모두 OFF라면 다시 켜서 실험하지 않고 다음 후보를 검토한다. 활성 상태라면 Auto ads 실험에서 Ad intents의 링크/앵커/칩을 함께 OFF로 하는 'Ad intents 형식군 OFF' 변형만 비교한다. 별도의 Anchor ads와 Vignette ads는 이 변형에서 변경하지 않는다. 세 종류별 효과를 분리하고 싶으면 별도 후속 실험으로 진행한다. 기존 보고서에서 이 형식군의 직접 수익 기여가 $0.20이었다는 것이 선정 이유이며 수익 손실 2.1%를 보장하는 뜻은 아니다. [Ad intents 실험 지원](https://support.google.com/adsense/answer/6321880?hl=en)
6. **실험 UI:** Optimization → Experiments → Create new experiment → Auto ads → quizeey.com → Intent-driven formats에서 해당 형식군 해제 → Start experiment → 이름 `quizeey_ad_intents_off_2026` → Automatically choose winner OFF → Run experiment. 사이트당 진행 가능한 Auto ads 실험은 하나다. 계정에 진행 중인 실험이 있거나 옵션이 제공되지 않으면 현재 화면을 확인한 후 조정한다. [실험 생성](https://support.google.com/adsense/answer/9726342?hl=en)
7. **후속 후보:** 실제 큰 앵커/조작부 겹침이 확인되면 Anchor의 동적 확장·위치부터, 이후 전면 광고 추가 트리거/간격을 한 요소씩 평가한다. Side rail은 수익 비중 6.0%, 가시성 92.47%이므로 단순히 모바일 스크린샷을 근거로 끄지 않는다. 수동 측면 광고와의 실제 중복이 있는지부터 확인한다. Multiplex는 In-page 수익을 분리하기 전 일괄 중단하지 않는다.

## 판단 한계와 측정 요청

제공 형식별 수익의 5%는 약 **$0.47**다. 이 규모와 자료만으로 2주 만에 5% 수익 비열등성을 입증하기는 어렵다. 단위 노출별 수익 분산·실험군별 분모도 없어 정확한 필요 표본을 계산할 수 없다. 이전의 '-5% 이내' 제안은 사업상 목표안이며, 지금 검증됐거나 반드시 허용해야 하는 손실 한계가 아니다.

실험 수익은 AdSense Result ready와 불확실성을 보고, UX는 새 계측 버전의 응답·완료·재방문을 함께 본다. AdSense 실험군이 GA4에 자동 전달되는 것으로 가정하지 않는다. 두 시스템에 공통 실험군 식별이 없으면 AdSense의 수익 A/B 결과와 GA4의 전체 추세 감시는 구분한다.

다음 자료는 새 계측값 수신 후의 GA4 이벤트 이름별 보고서 또는 학습 퍼널이다. 먼저 practice_start, answer_submit, practice_result, practice_complete가 수집되고 ad_policy가 balanced_v1인지 확인한다. 단순 이벤트 총횟수의 나눗셈을 세션 완료율로 해석하지 않는다. GA4 Funnel exploration의 사용자 퍼널을 사용한다면 사용자 기준 완료율이라고 명시하고, 기존 세션 기준 목표와 혼용하지 않는다.

현재 사용자에게 바로 필요한 추가 화면은 **Overlay formats의 Advanced settings를 펼친 화면**이다. 원본 CSV와 제공 스크린샷을 보존하며 이 분석을 위해 운영 사이트를 테스트하거나 설정을 변경하지 않았다.

## 2026-10-25 추가 스크린샷 — 전면 광고 완화 실험 우선

추가된 Advanced settings 화면에서 아래 편집 상태가 확인됐다. 계정에 저장·적용됐는지는 스크린샷만으로 확인하지 않는다.

| 옵션 | 화면에 보이는 값 |
| --- | --- |
| Allow dynamic anchors | ON |
| Allow anchor ads on screens wider than 1000px, like desktop | ON |
| Select anchor ad position | Top or bottom |
| Select side rail ad position | Left and right |
| Vignette ad frequency | 1 minute |
| Allow additional triggers for vignette ads | ON |
| Allow vignette ads on screens wider than 1000px, like desktop | ON |

현재 전면 광고는 가장 짧은 1분의 최소 간격과 추가 트리거를 허용한다. Google은 추가 트리거에 30초 이상 입력이 없다가 다시 조작하는 상황과 탭으로 돌아오는 상황 등을 포함한다고 설명한다. 문제를 읽고 생각한 뒤 답을 고르는 학습 흐름에도 영향을 줄 수 있다는 추론이다. 실제 방해 발생률을 측정했다는 뜻은 아니다. [추가 트리거 설명](https://support.google.com/adsense/answer/16853623?hl=en)

이제 세부 값이 확인됐으므로, 기존 Ad intents 우선 제안보다 **전면 광고 완화 정책의 비교를 먼저** 권한다.

- 원본: 현재 전면 광고 설정.
- 변형: **Vignette ad frequency = 10 minutes**, **Allow additional triggers for vignette ads = OFF**.
- 이 둘은 '전면 광고 완화'라는 하나의 운영 정책 묶음으로 비교한다. 두 매개변수의 개별 인과효과는 분리할 수 없다. 그 외 Anchor/Side rail/인페이지/Ad intents/데스크톱 허용 설정은 이 실험에서 동시에 바꾸지 않는다.
- 10분은 다시 전면 광고가 표시될 수 있는 최소 간격이다. 10분마다 반드시 표시한다거나 1분 대비 수익이 90% 감소한다는 뜻이 아니다. [빈도 설정](https://support.google.com/adsense/answer/13956167?hl=en)
- 계정에서 진행 중인 Auto ads 실험을 확인하고, 자동 최적화 및 자동 승자 적용을 고정한 상태에서 진행한다. Apply to site → Run experiment first → 실험 이름 `quizeey_vignette_10min_no_extra` → 자동 승자 선택 OFF → Run experiment. 저장 UI에서 제공되는 실험 경로를 사용한다. [실험 생성](https://support.google.com/adsense/answer/9726342?hl=en)
- 전면 광고의 과거 수익 기여는 13.8%이므로 수익 유지가 보장되는 변경은 아니다. AdSense 수익 실험과 GA4 전체 UX 추세를 구분하며, 기존 자료로 충분한 검정 기간이나 5% 손실 한계 충족을 단정하지 않는다.

후속 앵커 검토 후보는 **Allow dynamic anchors OFF**, **Bottom only**다. 동적 앵커는 표준 앵커보다 크게 확장될 수 있으므로 작은 화면에서 검토할 가치가 있다. 이는 후속 정책 후보이며 지금 전면 광고 실험과 함께 적용하는 지시가 아니다. 데스크톱 앵커·Side rail 전체 비활성화는 플랫폼×형식 수익과 실제 겹침을 확인한 뒤 판단한다. [앵커 설명](https://support.google.com/adsense/answer/15484692?hl=en)

이번 후속 검토에서도 계정 설정·앱 코드·운영 배포를 변경하지 않았다.
