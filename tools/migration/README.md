# Offline migration tooling

`audit.py` takes normalized JSON with the six legacy table names and snake_case field names. Actual MySQL5.7.30 metadata is now recorded in `verified_schema.json`; the approved SSH exporter uses the real column list and preserves source PKs as decimal strings. JPA guesses and the historical five-table DDL are not the export contract.

```powershell
python -m unittest discover -s tools/migration -p 'test_*.py'
python tools/migration/audit.py .modernization/exports/normalized.json
python tools/migration/disqus_import.py .modernization/exports/disqus.xml .modernization/exports/disqus-thread-mapping.json
# Approved source snapshots only, in their existing owner-private directory:
python tools/migration/audit.py .modernization/exports/source-265c3ca16e/normalized.json --output-dir .modernization/exports/source-265c3ca16e/rehearsal --allow-raw-relational-errors
python tools/migration/source_contract.py .modernization/exports/source-265c3ca16e
python tools/migration/rehearse_snapshot.py .modernization/exports/source-265c3ca16e
```

It checks PK/composite duplicates, relationships, multi-answer sets and legacy counters, and writes deterministic counts/hashes/correct sets plus idempotent **raw staging** SQL into ignored `.modernization/`. It never connects to a DB, alters live data, or claims that final relational ETL has passed. Reports contain no source question or author text; staging SQL can contain private source fields and must stay outside Git.

The owner-supplied five-table DDL is historical. Verified live fields are `answer_yn`/`multi_answer_yn`, test metadata includes `test_nm_eng/url/inqr_seq`, question explanation/reference widths are 4000/1000, and explanation is the sixth table. The auditor still accepts historical flag aliases for validation, reports conflicts and retains the original names in raw staging/hashes. Schema3 reconciliation never assigns choices to one arbitrary duplicate question ID: ambiguous correct sets are null and publication remains blocked. Missing IDs, duplicate PKs, NUL/unpaired-surrogate text prevent even raw staging. `--allow-raw-relational-errors` only permits private lossless preservation of identifiable rows. Inserts are batched at500 rows for bounded, replayable local imports.

`source_contract.py` validates every row's exact verified column set, nullability, integer range, varchar width and UTC source timestamp. Detailed HTML references and a duplicate relationship review stay private. `relationship-review.html` is offline/script-free, escapes source markup and blocks all external requests with CSP. Public evidence contains fixed aggregate names/counts only. No repair or publication is performed.

`typed_archive.py` emits a transaction that converts raw JSONB into the private `quizeey_legacy` schema from migration005. Source IDs, duplicate natural keys, nullable fields and counter values remain intact. TIMESTAMP values are imported with explicit UTC; typed semantic hashes compare equivalent instants while raw hashes preserve original strings. Five identity sequences start at least at the verified source AUTO_INCREMENT watermark or maxID+1. Source created_date has ON UPDATE semantics; no missing original creation history is invented. There are no public policies or grants, including service_role.

`rehearse_snapshot.py` checks snapshot hashes, owner-only ACL and the type contract, then creates a NEW loopback-only SCRAM-authenticated PostgreSQL cluster on55434. It refuses an occupied port, uses no existing DB, imports raw/typed twice, checks all payloads and exam/version/correct-set/counter hashes, tests sequences and denied anon/authenticated/service_role access, restores a backup and rechecks. PostgreSQL files, backups and logs inherit the snapshot's private ACL; DB stderr and source content are never printed. The server stops in finally. This is a local archive rehearsal, not final public serving ETL, Supabase-account RLS proof, whole-instance recovery or reverse migration of new forum writes. Source-related outputs must remain in ignored private storage.

The owner confirmed deletion of751 questions **from the new-service migration dataset only**, retaining source MySQL and backups. Materialization requires both `--approved-delete-count 751` and the reviewed `--approved-question-set-sha256`; a changed count/ID set aborts. The owner-private output is `new-service-dataset.json`, with a separate deleted-ID manifest and count/hash evidence. Never substitute the full original archive for this filtered serving input.

`content_etl.py` maps unique approved exam/version/question/choice keys to original IDs in migration006's relational content tables. It fails on any source type/relationship/flag ambiguity and retains nullable values, UTC timestamps, all correct choice IDs and source counters. Source explanation2,183 rows stay in the filtered dataset for the pending native-forum import, outside these five core content tables. `rehearse_content.py <private-snapshot-directory>` validates the approved dataset and deleted-ID hashes, creates a NEW owner-private SCRAM loopback cluster on55435, replays twice, compares every target value/ID and correct set, probes FK/unique violations and sequence positions, denies public/service roles, restores a backup and verifies again. It never connects to source MySQL or hosted Supabase. Roles remain closed; production publication/transport is a separate gate.

`node tools/modernization/audit_learning_html.mjs <private-snapshot-directory>` applies the actual app sanitizer to all original text fields. Public evidence contains only counts/hashes. The private offline review includes escaped before/after source HTML, CSP blocks external I/O, and no source bodies are printed. Technical-token restoration is classified separately from unexpected parsed-text changes; neither replaces full browser/content-rights review.

`prepare_local_content.py <private-snapshot-directory>` verifies the approved filtered dataset and751-ID manifest, then writes `local-content.json` and its hash manifest inside the existing private folder. It excludes source author names and user-post bodies. The app's `local-archive` source validates this location, schema and relationships, requires Basic authentication/loopback/local stage and refuses hosted use. `node tools/modernization/verify_local_content.mjs <private-snapshot-directory>` starts and stops an authenticated loopback app, tests actual API values and browser grading/resume, and blocks external browser requests. Only aggregate evidence is public; the screenshot and runtime logs remain private. `.vercelignore`, runtime-only filesystem reads and tracing exclusions prevent accidental source inclusion in deployment artifacts.

`legacy_explanations.py` maps retained MySQL explanations to deterministic UUID topics/posts with `mysql:question:<original-id>` and `mysql:explanation:<original-id>` source keys. Body and display-name strings remain exact: the original additional-explanation UI used `innerText`, so HTML stripping would change legacy text. React escapes the native post text. Original nullable created_date falls back explicitly to modified_date and is recorded in the private mapping; no original creation history is inferred. All imports start pending, without Auth accounts or guest ownership. Replays use `ON CONFLICT DO NOTHING` so later moderation is not reset. Legacy discussions were keyed by question only; the app's reserved import namespace preserves their shared locale scope while new topics retain their selected locale. `rehearse_explanations.py <private-snapshot-directory>` uses existing migrations002–004 in a new owner-private SCRAM loopback cluster55435, replays twice, reconciles all values/IDs/UTC, verifies pending RLS and unauthorized edit403, probes moderation-preserving replay and the actual app query for both locales, then dumps/restores and stops the cluster. This performs no hosted import and does not make the source author's name an authenticated identity.

`disqus_import.normalize(xml, reviewed_mapping)` strips email/IP, excludes deleted/spam/private records, keeps source IDs and parents, and never creates accounts/capabilities. Thread mapping is explicit; a historic URL is not routing proof. Missing visibility evidence stays pending. Duplicate/unmapped/cross-thread or unavailable parents block final import. Review timestamp semantics and sanitize remaining display names/text on rendering. A production XML export has not been supplied.
